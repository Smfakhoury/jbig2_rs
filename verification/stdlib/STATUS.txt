REVIEWED PROOF-ONLY STANDARD INTERFACE

The private integration adds one allocator-generic Vec::capacity interface.
It has no requires/ensures facts about capacity, length, reservation, usable
allocation size or equality between observations. The standard declaration
is nevertheless an explicit additional trusted boundary, not a native codec
proof and not normative approval.

The delegated coordinator's technical review authorizes this exact interface
for private integration under the user's existing engineering/review/merge
authority. This is not a new named-human standards adjudication or owner
public-release/visibility decision. The decision and limitations are tracked
in issue 116. The reviewed source/manifest identities are recorded separately
and checked by the runtime trust audit; unreviewed trusted declarations remain
forbidden in the decoder, project models and proofs.

The verification-only jbig2_capacity_interface dependency isolates the
standard-interface macro's generated unsafe glue. The native decoder keeps
forbid(unsafe_code), no runtime dependencies and the existing MSRV unchanged.
No standard return-value axiom, allocator fact or toolchain upgrade is added.

The checked observe_capacity_budget function calls the getter once and
checks conversion, multiplication and the accepted limit. Its strong
missing-limit mutant must fail and its corresponding weaker control must
pass. It does not approve the trusted declaration or prove allocator behavior.

From the repository root with the existing tooling environment:
  python3 verification/stdlib/validate_capacity_interface.py --verus /path/to/pinned/verus
  python3 verification/stdlib/validate_selected_cache.py --verus /path/to/pinned/verus

Selected queries run in isolated copied source/dependency graphs. Cargo focus
stores its root under verus-partial; each query invalidates only the
production package in that exact target. This retains immutable dependency
metadata but never reuses a solver query, lifetime or erasure check. The real
cache/relocation regression requires unchanged source bytes/timestamps and
actual fresh counts 1/2/1/4. Missing reports or failed invalidation are fatal.
