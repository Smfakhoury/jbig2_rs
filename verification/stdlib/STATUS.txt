PROOF-ONLY STANDARD INTERFACE

The verification dependency graph contains one allocator-generic immutable
Vec::capacity getter signature. It has no requires/ensures facts about capacity,
length, reservation, usable allocation size or equality between observations.
It is an explicit standard-library trust boundary, not a codec theorem.

The exact package, source, signature and hashes are recorded in review.json
and checked by the runtime trust audit. Unknown trusted declarations, changed
signatures and added return-value facts fail validation.

The verification-only jbig2_capacity_interface dependency isolates the standard
interface macro's generated glue. The native decoder has no dependency on it
and retains forbid(unsafe_code). No allocator fact or equality axiom is added.

observe_capacity_budget calls the getter once and checks conversion,
multiplication and the configured limit. Removing the limit must fail the
strong proof while its selected weaker control passes. This establishes the
numeric guard, not allocator behavior or total process-memory bounds.

From the repository root:
  python3 verification/stdlib/validate_capacity_interface.py --verus /path/to/pinned/verus
  python3 verification/stdlib/validate_selected_cache.py --verus /path/to/pinned/verus

Queries run in isolated source/dependency copies. Each selected query invalidates
the production package in its exact target while retaining immutable dependency
metadata. Solver, lifetime and erasure checks are not reused.

The cache/relocation regression requires unchanged source bytes/timestamps and
actual fresh counts 1/2/1/4. Missing reports or failed invalidation are errors.
Whole-crate verification and compilation remain separate requirements.

Vector capacity, allocator requested payload, usable allocation size and
process RSS are different quantities. This interface supplies no proof that
they are equal and no independent JBIG2 conformance guarantee.
