Proposed standard boundary
--------------------------
The verification-only jbig2_capacity_interface_proposal path dependency adds
one allocator-generic Vec::capacity interface with no requires/ensures facts
about returned capacity, vector length, requested reservation or allocator
usable size. The native decoder has no new dependency and retains
#![forbid(unsafe_code)] unchanged.

The standard-interface macro generates unsafe verifier glue. It is isolated
in the proposed verification dependency, not allowed inside the decoder
crate's unsafe-forbidden scope. That dependency is an additional unapproved
standard-library trust boundary, even though its return is unconstrained.
No standard-trust approval, normative approval or release acceptance is
implied by a successful candidate proof.

Candidate implementation
------------------------
- MMR preparation executes the same retained-capacity release, observation
  and rejection logic in ordinary and proof builds. Saturating conversion
  matches the old native unwrap_or behavior without an unsupported getter
  or Result::unwrap_or in the application proof body.
- An explicit compile-time guard requires pointer widths no larger than the
  u64 resource-accounting domain. On supported 32/64-bit targets, observed
  usize capacities convert without a fallible error path or truncation.
- Bitmap allocation checks the actual reserved Vec capacity after fallible
  reservation, not only the requested logical byte length.
- Borrowed-symbol pointer storage checks requested preflight ordering first
  and the actual reserved pointer capacity after reservation.
- Owned collection tracks logical decoded bitmap bytes separately from
  observed allocated bitmap bytes; existing decoded-byte error priority is
  retained, while memory checks use the appropriate observed counter.
- Candidate postconditions include retained/allocated counter bounds and
  exact requested/peak arithmetic. They do not prove allocator usable size,
  process RSS, allocation peak, arbitrary callbacks or normative conformance.
